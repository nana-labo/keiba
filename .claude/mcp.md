# MCP 構成メモ（keiba）

## 何を繋いだか

`.mcp.json` に **Playwright MCP**（`@playwright/mcp`）を1つだけ登録している。

`keiba-yosou` スキルの手順のうち、Web検索では原理的に埋まらないのが次の2つで、
どちらもログイン済みブラウザがあれば解ける。逆にここ以外は既存の道具で足りている。

- **Step 4（データ収集）** — 確定オッズ、調教後馬体重、追い切り時計、パドック気配。
  netkeiba・JRA公式はJSレンダリングとログインが前提で、`WebFetch` では本文が取れない。
- **Step 5（X検索・必須）** — 現状は `site:x.com` を付けた WebSearch のスニペット頼み。
  水曜夜〜木曜朝に出る調教評価・回避情報の取りこぼしが大きい。ログイン状態の
  タイムラインを直接読めれば、この工程の精度が一番変わる。

## 使う前に

初回はブラウザを起動して netkeiba と X に手でログインしておく。Playwright MCP は
既定で永続プロファイルを使うため、ログイン状態は次回以降のセッションに引き継がれる
（`--isolated` を付けると毎回破棄されるので付けないこと）。

収集先の利用規約とレートには配慮する。人が読む速度を超える連続取得はしない。

## この設定が効く範囲

`.mcp.json` は **cwd がこのリポジトリの Claude Code セッション**にのみ適用される。
予想を生成しているのがこのリポジトリ以外（Cowork など）なら、同じ内容を
そちらのユーザー設定にコピーするか、claude.ai のコネクタ側で繋ぐ必要がある。
このファイルは「推奨構成の正本」として置いてある。

## 見送ったもの

- **AccuWeather**（認証不要・claude.ai コネクタ）— 気温／降水確率／風は構造化して取れるが、
  スキルが必須としている**含水率・クッション値・芝丈は JRA 公式にしか無い**ので、
  結局ブラウザ側の仕事が残る。入れるなら `.mcp.json` ではなく claude.ai のコネクタから。
- **Firecrawl** — 有料枠に加え、netkeiba を第三者サービス経由で取得する形になる。
  自分のブラウザで見る Playwright のほうが筋がいい。
- **Airtable / Notion / Neon** — 印と着順の突合（回顧）用のDB。必要になるのは
  検証の運用が回り始めてからで、それまではリポジトリ内の JSON/CSV で足りる。
- **Vercel** — 公開は GitHub Pages（`.github/workflows/pages.yml`）で完結している。

## 注意

`main` は別プロセスが生成する `deploy <sha>` コミットで更新されている。
このファイル群を `main` に入れる場合、デプロイ側が全体同期をしていると消える可能性がある。
